# 河道巡查叙述的方位解释与补核计划

reaches 是有向岸段，可进入位置用 entry 表示。landmarks 把俗名和河网节点对应起来。handovers 保存巡查队交接原话。patrol 给出巡规定义和临时入场限制。flowNotes 保存值班采用的流向和班组口称。

资料保存在 `data/inputs.json`，采用 UTF-8 JSON。记录、人员、地点和业务编号均为合成内容。

运行环境为 Node.js 22.23.4，资料工具和测试使用 Node.js 标准库。

```sh
npm run inspect:data   # 列出资料记录数
npm run board          # 打印中文值班看板
npm run board:json     # 输出机器可读的判定结果
npm test               # 运行全部测试
```

## 工具链

| 模块 | 职责 |
| --- | --- |
| `scripts/parser.mjs` | 拆分中文叙述小句，识别“过了/走到/没到/远望/过桥/原路退回/直到/转弯/进去”等动作、地标俗名、岸别、方向词；重名俗名保留全部候选节点，不就近选名 |
| `scripts/graph.mjs` | 分岸有向河网：水文方向取 `from→to`，人员步行按无向邻接枚举路径，但每条路径保留岸段身份，不连通的近岸段不会被补成走过 |
| `scripts/adjudicate.mjs` | 把证据原子放到河网上推断每条岸段状态、生成待核对问题、校验补核任务，并给出派单草案 `planRecheck` |
| `scripts/board.mjs` | 值班看板（中文）与 `--json` 输出、`plan <岸段> [班组]` 派单命令 |

## 判定口径（与巡规一致）

- **只有实地动作算完成**：`pass/walk/enter` 且路径唯一可落图时记 `covered`。巡规 `patrol.qualifying` 之外的动作不算。
- **看到对岸 ≠ 走到对岸**：“隔河望/远望/看到对岸”记 `remote-only` 问题；“过桥/走到对岸”（cross）只证明节点到场（`presence`），不沿路径补岸段覆盖。
- **明确漏查**：地标能唯一落图时记 `missed`，可安排补核；地标有歧义或“下一个闸”这类未落图名词时，只给候选岸段与原句提问，不替班组选一个解释。
- **俗名歧义**：两座“石桥”（节点 b、c）在澄清前保留多路径候选；后来的“X 指 Y”叙述（如 H2）统一先应用再重判，澄清目标本身仍有歧义时保持 `unresolved`。
- **流向两套叫法**：“下游/顺水”始终保留水文方向解释；当 flowNotes 定义了口头“顺队”路线且语境在支沟时，再追加口头方向解释，两者并存不做二选一。
- **原路退回**：退回不产生新岸段；入支后“原路退回再从闸边进去”，空间上靠近但不连通的岸段不得记为走过。
- **入口限制**：`patrol.blockedEntries`（桥、闸、封闭栈道）中的节点不能作为来路起点，也会在补核任务上标注封闭提示。
- **补核纪律**：
  - 已派出未回报的任务不产生覆盖，计划路线不等于完成；
  - 同一岸段不允许两个在岗任务同时认领，违反时报 `duplicate-dispatch`；
  - 有候选问题的岸段 `planRecheck` 直接拒单（`needs-clarification`），已覆盖岸段拒单（`already-covered`）；
  - 回报出现任务岸段端点之外的地标（“从另一座桥转弯”）时报 `recheck-route-conflict`，原班解释与新班覆盖一起重判，不直接销单。

## 岸段状态

`covered`（实地完成）/ `remote`（仅远望）/ `missed`（确定漏查）/ `conflict`（同段既称走过又称漏查）/ `unknown`（证据不足或候选未确认）。每条证据都带 `recordId` 与原句，可回查；看板同时列出当班入口限制。
